# 02. UI 구현 지침

## 디자인 방향
- 이미지 첨부가 현재 대화에 제공되지 않았으므로, 특정 이미지 디자인을 추측하지 않는다.
- 포켓몬 도감/게임 도구의 느낌을 주는 밝고 친근한 카드형 인터페이스를 사용한다.
- 배경은 아주 옅은 회색 또는 따뜻한 흰색, 주요 강조색은 포켓몬을 연상시키는 노란색으로 한다.
- 타입은 색상만으로 구분하지 말고 타입 이름 텍스트와 함께 표시한다.
- 과도한 애니메이션, 번쩍이는 효과, 복잡한 장식은 피한다.

## 레이아웃
- 중앙 정렬 메인 컨테이너, 최대 너비 약 960px
- 상단: 작은 심볼/서비스명과 설명
- 검색 카드: 넓은 입력창, 검색 버튼, 예시 검색 칩
- 결과 카드: 이름·타입 배지, 약점/저항/무효 섹션, 공략 팁
- 하단: 최근 검색, 피드백 입력, 피드백 목록
- 모바일에서는 한 열로 쌓고 버튼은 누르기 쉬운 높이(최소 44px)를 확보한다.

## 상태별 화면
- 초기: 사용 방법과 예시 검색 노출
- 로딩: 버튼 비활성화, 진행 표시와 “상성을 분석하고 있어요” 문구
- 성공: 결과 카드 노출
- 입력 오류: 입력창 근처에 짧은 안내
- 서버 오류: 재시도 가능한 안내
- 피드백 전송 중: 전송 버튼 로딩 처리
- 피드백 없음: 첫 피드백을 권하는 빈 상태 표시

## 접근성
- 모든 입력에 label을 연결한다.
- 버튼은 실제 button 요소를 사용한다.
- 키보드 포커스 테두리를 제거하지 않는다.
- 색 대비를 확보하고, 상태를 색만으로 전달하지 않는다.
- 결과 갱신 시 적절한 `aria-live="polite"` 영역을 사용한다.

## 완료 기준
- 360px, 768px, 1280px 화면에서 가로 스크롤이 생기지 않는다.
- 검색·피드백 버튼이 모바일에서도 충분히 크다.
- 로딩/오류/빈 상태가 각각 구분된다.
