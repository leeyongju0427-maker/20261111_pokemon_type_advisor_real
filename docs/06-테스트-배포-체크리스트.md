# 06. 테스트 및 배포 체크리스트

## 기능 테스트
- [ ] 피카츄를 입력하면 포켓몬 데이터가 확인되고 결과가 표시된다.
- [ ] 존재하지 않는 이름은 결과를 꾸며내지 않고 안내한다.
- [ ] 빈 입력은 API 요청 없이 입력 안내를 표시한다.
- [ ] Enter 키로 검색할 수 있다.
- [ ] 연속 클릭 시 중복 요청이 방지된다.
- [ ] 최근 검색 5개가 저장되고 삭제된다.
- [ ] 피드백 작성자 생략 시 익명으로 저장된다.
- [ ] 빈 피드백과 500자 초과 피드백은 거부된다.
- [ ] 피드백 저장 후 최신순 목록에 나타난다.
- [ ] 새로고침 후 저장된 피드백이 유지된다.
- [ ] 피드백이 없을 때 빈 상태가 보인다.
- [ ] API/DB 오류가 한국어로 표시된다.

## 상성 정확도 테스트
- [ ] 단일 타입 약점·저항·무효를 검증한다.
- [ ] 복합 타입에서 4배/0.25배 계산을 검증한다.
- [ ] 0배 특성 등 타입 상성표 외 특성 효과를 별도 주의사항으로 표시한다.
- [ ] 특성 미확인 상태를 확정된 특성처럼 표시하지 않는다.
- [ ] 폼/세대에 따라 결과가 달라질 수 있다는 안내가 있다.

## 보안 테스트
- [ ] OpenAI 키가 HTML/JS 파일에 없다.
- [ ] Supabase service role 키가 클라이언트에 없다.
- [ ] `.env`가 Git에 포함되지 않는다.
- [ ] 사용자 입력이 스크립트로 실행되지 않는다.
- [ ] 서버 로그에 키와 민감한 입력이 기록되지 않는다.
- [ ] API 요청 제한이 작동한다.

## 반응형 및 접근성 테스트
- [ ] 360px 모바일에서 가로 스크롤이 없다.
- [ ] 태블릿과 데스크톱에서 레이아웃이 자연스럽다.
- [ ] 키보드만으로 검색과 피드백 제출이 가능하다.
- [ ] 포커스 표시와 입력 라벨이 있다.
- [ ] 성공/오류/로딩 상태가 색상 외 텍스트로도 전달된다.

## Vercel 배포 순서
1. GitHub 저장소에 코드를 올린다. 단, `.env`는 제외한다.
2. Vercel에서 해당 저장소를 Import한다.
3. 프로젝트 Settings의 Environment Variables에 다음 값을 등록한다.
   - `OPENAI_API_KEY`
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY` 또는 서버 전용 `SUPABASE_SERVICE_ROLE_KEY`(선택한 보안 설계에 따라 하나만 사용)
   - `OPENAI_MODEL`(선택한 모델명)
   - `ALLOWED_ORIGIN`(필요한 경우)
4. Supabase SQL Editor에서 `supabase/schema.sql`을 실행한다.
5. Deploy를 실행한다.
6. 배포 주소에서 검색과 피드백 저장/조회 테스트를 수행한다.
7. 환경 변수를 변경했다면 재배포한다.

## 환경 변수 예시
`.env.example`에는 실제 키를 넣지 않는다.
```env
OPENAI_API_KEY=
OPENAI_MODEL=
SUPABASE_URL=
SUPABASE_ANON_KEY=
# 또는 서버에서만 사용하는 경우:
SUPABASE_SERVICE_ROLE_KEY=
ALLOWED_ORIGIN=http://localhost:3000
```
